# ADR 0003: Argon2id password hashing, pepper versions and password policy

Status: Accepted (M5a-1). Parameters to be confirmed by the owner's `npm run auth:bench` on real hardware.

## Decision

- **Algorithm:** Argon2id through `@node-rs/argon2` (native, Node runtime only). Better Auth's default scrypt is replaced by our own `hash`/`verify` (M5a-2).
- **Parameters:** memory 64 MiB (`m=65536`), time 3, parallelism 1, 32-byte output, a random 16-byte salt per hash (generated by the library). OWASP's floor is 19 MiB / t=2 / p=1; we never go below it. The parameters are one constant (`ARGON2_PARAMS` in `src/server/security/password.ts`).
- **Pepper:** a server-side secret passed to Argon2 as its `secret`. It lives only in the environment, never in the database.
- **Stored format:** `pv<pepper version>:<PHC string>`, for example `pv1:$argon2id$v=19$m=65536,t=3,p=1$<salt>$<hash>`. The PHC string already holds the parameters and salt; the prefix records which pepper was used.
- **Normalization:** every password is normalized with Unicode **NFKC** before length checks, the breach check and hashing, so the same password typed on another keyboard or in another Unicode composition is one password.
- **Policy:** 12 to 128 characters (counted in code points after NFKC), spaces and any Unicode (Arabic included) allowed, **no composition rules**, a NUL byte refused, and **any** appearance in the Pwned Passwords corpus rejected (k-anonymity: only the first five hex characters of the SHA-1 leave the server, with `Add-Padding`). The breach check **fails open** if the service is unreachable (a third-party outage must not stop registrations); the result says the check was skipped.
- **Timing:** logins of unknown accounts spend one dummy verification (`verifyAgainstDummy`), and flows that differ by "email exists" are padded to a minimum duration (`withMinimumDuration`). The expensive part of those flows, sending email, happens through the outbox (ADR 0022), outside the request.
- **Input limit:** anything over 1024 characters is "not valid" without spending 64 MiB on it.

## The pepper: losing or changing it invalidates every stored password

A hash made with pepper P cannot be verified without P. If `PASSWORD_PEPPER` is lost, or edited, **no user can sign in with their old password** and every one must reset it. Therefore:

1. Generate it once (`openssl rand -hex 32`), **before the first real registration**, and back it up in a password manager. It is not recoverable from the database.
2. Never edit or delete a pepper that has hashes. Never reuse the value for another secret.
3. Production and any environment sharing the production database must use the same value.

## Rotating the pepper (no password resets)

`PASSWORD_PEPPER` is **version 1**. To rotate:

1. Generate a new value and add it as `PASSWORD_PEPPER_V2` (keep `PASSWORD_PEPPER` unchanged). Deploy.
2. Set `PASSWORD_PEPPER_CURRENT_VERSION=2`. Deploy. New hashes now use `pv2:`; `pv1:` hashes still verify.
3. Each successful login whose hash is `pv1:` returns `needsRehash: true` (also when the Argon2 parameters changed); the login flow (M5a-2) then stores a fresh hash. Users who never sign in keep `pv1:` and keep working.
4. Only when **no** `pv1:` hash remains (count them in the database) may `PASSWORD_PEPPER` be retired. Until then it must stay. Accounts still on `pv1` after a long time can be forced through a reset.

The boot validation fails when `PASSWORD_PEPPER_CURRENT_VERSION` has no matching pepper, or any pepper is shorter than 32 characters. Changing Argon2 parameters follows the same path (rehash at next login).

## Consequences

`@node-rs/argon2` is a native addon: it ships a binary per platform as an optional dependency (Windows `win32-x64-msvc` included), and is listed in `serverExternalPackages` so Next does not bundle it. It was exercised inside a production Next server in the sandbox. 64 MiB per hash means concurrent logins hold memory: 20 at once is about 1.3 GB, which is why login has a per-IP and per-email rate limit (ADR 0021) and why `npm run auth:bench` exists.
